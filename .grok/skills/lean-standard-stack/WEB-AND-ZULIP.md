# Web, clicks, and the Zulip comment

Public web research is required before a community contribution. Search and fetch the target CONTRIBUTING guide, style guide, and the current AI policy. Record the URL. Do not rely on memory of those pages.

Logged-in clicks are a different gate. Zulip is not a connected connector. The agent cannot post to https://leanprover.zulipchat.com/, cannot drive the author's logged-in browser, and must not claim a click or a sent message that did not happen. A bot with the author's computer is the only path that can click in his browser. Until that exists, the agent prepares the comment and stops.

Mathlib forbids LLM-written Zulip and GitHub comments (https://leanprover-community.github.io/contribute/). The agent drafts. Benjamin Stanley Frohman rewrites in his own words and posts. The agent then records the thread URL. A draft is not a discussion.

The draft names the proposed module, the statement, what is narrower than the paper, whether `lake build` is green, and that a tool scaffolded the draft. It does not claim a prize problem is solved. Template: `assets/zulip-draft.md`.

Start in #new members if the author has not introduced himself. Use #mathlib4 for a concrete design. Use #PR reviews only after a PR exists.

Real writes this session can make are GitHub writes on a branch of a repo the author owns, with the Author line and no Grok `Co-authored-by`. Do not post the Zulip draft as a GitHub comment either.
