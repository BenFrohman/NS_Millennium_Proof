    Vacuity and model-adequacy findings in a Lean formalization of
                 conditional Navier–Stokes regularity

                                                 Abstract
          We report defects found in the Lean 4 companion formalization of two preprints on condi-
      tional regularity for the three-dimensional incompressible Navier–Stokes equations on the torus
      T3 (10.5281/zenodo.24079623, 10.5281/zenodo.24080310). An attempt to prove the stated “an-
      alytic bridge” target led instead to a kernel-checked proof of its negation: the solution object
      did not encode the equations, so a zero velocity field with lifespan 1 counted as a solution. The
      same object shows that the cited Beale–Kato–Majda hypothesis was uninhabitable, making four
      conditional theorems vacuously true. Independently, the abstract data structure used for the
      “three-way equivalence” presupposed global regularity, so that equivalence carried no informa-
      tion. We describe each mechanism, the exact Lean theorems that establish it, and the corrected
      encoding: solutions that satisfy the Navier–Stokes equations on a maximal lifespan, the BKM
      and Kato–Ponce estimates as named cited hypotheses, and non-vacuity lemmas. This note
      does not solve, and makes no claim about, the Clay Millennium Problem. Global
      regularity for large data (Clay Statement (B)) remains open; in the corrected repository it is a
      single explicitly labelled open target.


1    What was claimed
The repository BenFrohman/frohmanian-tether-conditional-regularity accompanies the two
preprints above. Its README and the file AnalyticBridgeTarget.lean stated:

    1. an open target analytic_bridge_unconditional, described as “Clay Millennium Problem
       Statement (B) on the periodic 3-torus”, with one intentional sorry, and explicitly flagged as
       using placeholder fields;

    2. proved conditional results clayB_iff_bkm_integrable, formB_implies_clayB, hypothesisB_implies_clay
       and formB_Hs_bound, each taking a cited Beale–Kato–Majda (BKM) continuation hypothesis
       BKMCriterion N as an argument;

    3. in FrohmanianTripleArchitecture.lean (the file archived with the Tether record), hypothesisB_implies_c
       and three_way_equivalence over an abstract structure NavierStokesUnifiedData.

All proved declarations passed a kernel audit (#print axioms reporting only propext, Classical.choice,
Quot.sound). That audit establishes that proofs are correct relative to the definitions; it says
nothing about whether the definitions model Navier–Stokes, nor whether hypotheses can ever be
supplied. The findings below are of exactly that second kind.

2    How the defects were caught
The user asked for a full proof of the open target. The procedure was:

    1. Read the exact statement and every definition it depends on.

    2. Ask which objects inhabit the hypothesis types. The structure NSSolution had fields solves_NS
       : Prop and maximal : Prop: these are data (arbitrary propositions chosen by whoever builds
       the object), not proof obligations. The lifespan Tstar was an arbitrary element of [0, ∞].

    3. Build the simplest object of the type with a finite lifespan, and prove the negation of the
       target in Lean, against the literal type of the declaration (read off with Lean’s type_of%
       elaborator in the first commit, so that no hand restatement could drift from the original).

    4. Re-use the same object against every hypothesis structure; check each abstract structure for
       a field that silently implies its conclusion.

Every finding is therefore a kernel-checked theorem, not an informal remark.


3    The counterexample and the refutation
Definition 1 (legacy zero object). For any norm package N and viscosity ν, zeroSolution N
� is the legacy NSSolution with u0 = 0, u(t, x) = 0 for all t, x, T ⋆ = 1, solves_NS := True,
maximal := True. Every remaining field (initial condition, periodicity, C ω smoothness of each u(t),
continuity of t 7→ N (u(t)) for the three norm functionals) holds because every function involved is
constant.

Theorem 2 (analytic_bridge_target_statement_false). The legacy target statement is false.

Proof. Take N with all norms identically 0 (zeroNorms), ν = 1, s = 3 > 5/2, u0 = 0. Then u0 is
periodic and N.Hs(3, u0 ) = 0 < ∞, so all hypotheses hold. The target asserts T ⋆ = > for every
solution object; for zeroSolution we have T ⋆ = 1 6= >. Contradiction.

Theorem 3 (not_nonempty_BKMCriterion). For every N , the legacy type BKMCriterion N is
empty.

Proof. A term of BKMCriterion N maps any solution object whose function t 7→ N.gradLinf(u(t))
is interval-integrable on every [0, T ] to a proof of T ⋆ = >. For zeroSolution N 0 this function is
the constant N.gradLinf(0), which is integrable on every bounded interval, but T ⋆ = 1 6= >.

Remark 4 (consequence). Each of clayB_iff_bkm_integrable, formB_implies_clayB, hypothesisB_implies_c
formB_Hs_bound has an argument of type BKMCriterion N. Since that type is empty, each theo-
rem is of the form ⊥ → P and is vacuously true (BKMCriterion_elim derives False from any such
argument). They were correct proofs of statements with no content.

5.5   Legacy material
Nothing was deleted. FrohmanianTripleArchitecture.lean is byte-identical. In AnalyticBridgeTarget.lean
the header now marks the file LEGACY, and the former theorem-with-placeholder (a false state-
ment) is kept verbatim as the proposition analytic_bridge_unconditional_statement, which
the refutation file negates.


6     What remains open

says: for every ν > 0∫ and every smooth, periodic, divergence-free u0 , every maximal classical so-
