## Limits and next release gate
The audit inventories all tags/releases and exact-commit retained CI. It does not establish a complete clean build or validate every paper. Root document/recursive tree and release metadata were inspected; exact-tag README/LICENSE/CITATION were additionally fetched for the four unreleased version/alias tags. Every new release should pin the reviewed SHA; record toolchain, inputs and actual test/audit scope; reconcile theorem/declaration counts and authorship; rebuild LaTeX/PDF and compare hashes; include matching source, certificate and license; verify that the DOI identifies the exact archived version (or is explicitly a related older project); and obtain explicit approval before publishing.
